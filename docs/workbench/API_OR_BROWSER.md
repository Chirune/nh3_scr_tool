# 正文获取：API 或浏览器

交付版：2026-10-15。源码包入口为 `OPEN_THIS.cmd`，Windows 便携包入口为 `CatalystWorkbench.exe`。打开板块1后可看到“获取正文：API / 浏览器”。本地准备打包，由用户上传 GitHub。

## 你怎么用

1. 在板块1选择论文，核对 DOI，并判定“保留”。
2. 点“获取正文：API / 浏览器”。弹窗显示所选论文、HTTP 错误码、服务器说明和两个入口。
3. **API 通道**：填写 / 验证出版社 API；已有配置可获取保留论文。没有取得正文时，可返回弹窗改用浏览器。
4. **浏览器通道**：点“打开浏览器并授权本次采集”。程序打开专用 Chrome，你在里面完成学校或出版社登录，返回论文并展开正文。程序每隔约2.5秒检查所选 DOI 的页面，最长等待15分钟。
5. 程序优先尝试页面声明的 PDF；也可由你直接在该专用浏览器内点击 PDF 下载。若没有取得原版 PDF，但当前已加载了正文，则保存网页正文与采集记录，并生成用于文本提取的可见正文排版件。
   如果登录后停留在出版社首页，可回到弹窗点击“已登录，返回论文”，让程序返回本次论文继续检查。
6. 此弹窗自动接收任务结果，核对文件、DOI及题名后关联论文。点“已接收正文 → 第二板块”继续提取。

如果专用浏览器出现验证码或登录不被接受，由用户在浏览器中处理；可改用“已有浏览器 + Zotero”。程序不会操作你日常浏览器里的其他标签页，学校密码和 Cookie 不会被导出到 API 设置或采集 JSON 中。

## 错误怎样显示

| HTTP | 含义与下一步 |
| --- | --- |
| 401 | 认证或 API 服务授权未通过；核对 Key 和已开通服务，也可改用浏览器。 |
| 403 | 当前请求被拒绝；核对机构识别、API 权限或文章权限，不能单凭此码认定学校没买。 |
| 404 | 当前入口没有找到内容；核对 DOI、入口和文献平台。 |
| 429 | 限流或额度限制；按服务器等待时间暂停，不连续重试。 |
| 没有 HTTP 响应 | 网络连接或超时；不伪造401/403。 |

错误码会出现在结果列表、论文详情、出版社单篇验证和获取方式弹窗中。浏览器成功之后，之前的API错误仍可追溯，不会被改写成API成功。

## 获取范围

- 浏览器权限只针对本次明确选择的论文任务；每篇需明确启动。当前浏览器入口不是无人值守批量遍历整个站点。
- 登录页、DOI不一致的页面、只有摘要的页面、错误页和身份不一致的PDF不会当作有效正文接收。
- 可见正文排版件明确标注“非出版社原版PDF”；其页码仅属于排版件，完整性仍需核对。排版件不包含可靠的原版曲线图，读图应另取原版PDF。
- 已有本地PDF不会被浏览器结果自动替换；原文件发生变化时保留待核对状态。
- 登录状态由专用 Chrome 资料目录管理，位于忽略目录 `runtime_data/browser_profile/`。任务、采集内容与接收文件保存在当前运行目录的“浏览器采集”下。关闭采集弹窗会请求停止本次任务。

浏览器入口需要本机 Chrome 与 `playwright` 依赖，不需要另装浏览器插件；原有采集插件和 Zotero 作为备选入口保留。浏览器能否实际取得付费全文，取决于用户与机构的访问权限。

自动流程已用真实 Chrome 和模拟登录页面测试；这不等于所有出版社的真实账户登录都已验证。

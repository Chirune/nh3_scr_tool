# 2026.10.15：API、浏览器与 Zotero 接收整合

本次本地交付基于 2026.10.09 三板块整合版。保持“文献获取与筛选 → 单篇证据提取与核对 → 编码、评分和模型输入准备”的流程。

## 这次增加了什么

- 正文获取窗口提供 API / 浏览器两种入口。列表、详情与单篇接口验证显示实际 HTTP 401、403、404、429 等状态，并给出中文解释；网络超时不会伪装成权限错误。
- 浏览器通道打开专用 Chrome。用户完成登录后，程序检查所选 DOI，优先接收原版 PDF，也可接收浏览器内手动下载的 PDF。若只能读取已加载正文，则保存可见 HTML、文本和带标记的正文排版件。
- 文件接收核对 DOI、题名、大小和完整性；登录页、摘要页、错误页、其他论文 PDF 不会作为合格全文接收。排版件页码明确区别于出版社页码，也不能当作原始曲线图来源。
- 保留已有浏览器插件和 Zotero 接收入口。插件可按需采集当前页的题录、摘要、可见正文、PDF 和补充材料链接；插件需重新加载当前包中的 browser_extension。
- 接入 Elsevier 官方全文 XML 解析、Wiley 官方 TDM 客户端、Springer Nature 官方客户端。Open Access / Metadata Key 与订阅 Full Text/TDM 权限分别处理。
- 扩展 OpenAlex、CORE、Semantic Scholar 等检索或开放获取通道；有无凭据、接口限流和内容权限分别记录。增加平台诊断与使用说明。
- 增加本机 Ollama 语义用途建议，减少逐条手选类别的负担。模型建议绑定原句与来源，用户确认后才采纳；模型文件不随包分发。
- 新增完整 Windows 便携包与可复现的本地构建脚本。便携包内置 Python 和依赖，三个板块、浏览器工作进程共用实际解释器，不再使用只冻结旧采集界面的 EXE。

## 实际验证到哪一步

2026-10-15 的真实网站测试：Nature 指定 Cu-CHA 论文取得 14 页出版社 PDF；MDPI 指定综述取得可见正文排版件。两者均进入文本/语义候选证据提取。

Elsevier 官方 API 仍返回 403；先前浏览器任务也未取得正文。此后直接操作日常 Chrome 的测试被电脑操作工具终止，不能据此宣称已解决 ScienceDirect 登录或下载问题。其他平台未逐一完成真实机构账户登录验证。

候选证据不是已审核的机器学习样本。目前没有据本轮新提取结果完成训练，也没有新增模型准确率或 DFT 验证结论。综述中的转述数据不能当成独立实验重复计数。

## 安装与操作

普通使用者下载 Windows 包，完整解压后双击 CatalystWorkbench.exe。需要 Windows 10/11 x64；浏览器采集另需已安装的 Google Chrome。Zotero、自有 API Key 与可选模型由用户自行配置。

开发者使用源码包：安装 Python 3.11/3.12 后双击 OPEN_THIS.cmd，或运行 scripts/setup_workbench.py --team-tools。原来的四个分板块包此次合并为一个源码包，统一入口仍可分别启动三个板块。

进入板块1 → 检索或导入 → 判定保留 → “获取正文：API / 浏览器” → 接收正文 → 进入第二板块核对原文 → 输出第三板块待编码数据。

升级时先完整解压到新目录；旧版 runtime_data 和 local_models 留在原处备份，再按需迁移。不要用源码包覆盖后误删本机数据。

## 公开范围与已知限制

公开源码、插件、合成示例、自动测试和使用说明。Windows 包额外包含运行依赖及其许可文件。不含任何用户 API 密钥、账号、浏览器资料、真实论文、科研审核记录、测试运行目录、模型权重或专利私人文件。

浏览器采集按单篇明确授权，不是无人值守抓取整个出版社。用户自行完成登录与验证。HTTP 403 只表示当前请求被拒绝，不能单凭它判断 API Key 无效或学校未订阅。

Windows 包为便携目录，EXE 必须与 runtime、源码及资源目录一起使用；不是单文件 EXE。没有代码签名，尚未在另一台干净电脑验收。
